# `quant_workflow_from_scratch.py` 量化流程审阅报告

## 1. 审阅结论

该脚本可以帮助初学者理解“数据加载 → 因子计算 → 因子检验 → 模型合成 → 组合构建 → 回测评价”的基本结构，但目前还不能用于判断策略是否真实有效。

当前版本存在几处会显著影响结果的前视偏差、交易时点假设和回测口径问题。输出的年化收益、夏普比率和策略优劣不宜直接作为投资结论。

脚本语法正常；若 PowerShell 中出现中文乱码，属于 UTF-8 显示问题，不是源码损坏。

## 2. 问题优先级汇总

| 优先级 | 问题 | 主要影响 |
|---|---|---|
| P0 | 使用未来标签是否为空决定今日股票是否入选 | 直接前视偏差，可能提前规避停牌、退市或数据缺失股票 |
| P0 | 使用完整 T 日行情生成信号并假设以 T 日收盘价成交 | 成交价格在信号完整形成前可能已不可获得 |
| P0 | 股票池过滤晚于截面标准化 | 非当日成分股、未来成分股污染历史截面 |
| P0 | 回测末端少算收益、多收一次调仓成本 | 回测收益和成本错配 |
| P1 | 等权因子未按 IC 方向调整 | 负 IC 的有效因子被反向使用 |
| P1 | 等权收益与换手率口径不一致 | 低估真实交易量和交易成本 |
| P1 | 缺失收益删除后重新等权 | 停牌等场景下出现免费资金重分配 |
| P1 | 基准并非真实或当日等权 CSI300 | 超额收益比较失真 |
| P1 | 未模拟涨跌停、停牌及 A 股交易成本结构 | 策略可交易性偏乐观 |
| P2 | OLS 目标与每日选股排序目标不完全一致 | 模型不稳定、样本外能力可能较弱 |
| P2 | 验证集没有真正参与模型选择流程 | train/valid/test 职责不清晰 |
| P2 | 夏普和最大回撤口径不标准 | 绩效指标与常见平台不可直接比较 |

## 3. 必须优先修复的问题

### 3.1 使用未来标签可用性筛选今天的股票

相关代码：第 274 行附近。

```python
clean_df = processed.dropna()
```

这里同时要求所有因子和 `LABEL` 非空，而当前 `LABEL[t]` 是 T+1 开盘到 T+2 开盘的未来收益。因此，如果某只股票在未来持有期停牌、退市或缺少行情，它会在 T 日就被排除。

这等于提前知道了未来持有期是否存在价格，属于直接的前视偏差。如果行情只读取到信号截止日，两日偏移标签还会使最后两个交易日缺少答案；当前代码会额外读取两个交易日用于结算，但打分股票池仍然不能依赖标签是否存在。

建议将数据拆成两种用途：

- 训练和 IC 检验：因子与标签均须非空。
- 验证期、测试期和实盘打分：只要求因子非空，不能参考标签是否存在。
- 停牌、退市和无法成交：由交易模拟单独处理。

简言之，训练和 IC 检验是“同时有题目和答案”，而打分必须“只看当时已知的题目”。验证集和测试集的标签只能在得分生成后用于事后评价，不能事先用于缩小候选股票池；否则会提前排除未来持有期停牌、退市或缺少行情的股票，形成前视偏差。如果模型选中了这类股票，应保留该次选股结果，再由交易模拟器根据停牌、涨跌停、退市等规则决定能否成交及如何保留持仓权重，不能因为 `LABEL` 缺失就提前删除或把资金无成本重新分配给其他股票。

### 3.2 CSI300 过滤发生在截面预处理之后

相关代码：第 266～283 行。

当前流程先对整个样本期内“曾经属于 CSI300”的股票合集做 MAD 去极值和 Z-Score，之后才过滤当日成分股。

因此，尚未进入或已经退出 CSI300 的股票会影响当日成分股的均值、标准差和去极值边界；未来才进入指数的股票也可能污染历史截面。

正确顺序应为：

1. 使用完整历史行情计算 rolling 因子，避免新入选股票缺少历史窗口。
2. 按日期过滤当日有效 CSI300 成分股。
3. 仅在当日股票池内执行去极值和标准化。

### 3.3 收盘信号对应收盘成交，假设不可实现

原脚本使用 T 日最终收盘价、最高价、最低价和完整成交量生成信号，却假设仍能按 T 日收盘价成交，时间上不可实现。当前改为以下统一口径：

```text
T 日收盘：完整行情确定并生成信号
T+1 日开盘：买入或调仓
T+2 日开盘：卖出或再次调仓
```

普通 A 股当天买入后不能当天卖出，因此持有到 T+2 开盘既给信号留出了计算和下单时间，也满足 T+1 交易限制。标签必须与实际持有区间一致：

```python
LABEL = open_.shift(-2) / open_.shift(-1) - 1
```

即 `LABEL[T] = open[T+2] / open[T+1] - 1`。训练、IC、策略收益和基准均应采用这一 open-to-open 区间。为了完整评价截至 `TEST_END` 的信号，行情读取范围会根据 Qlib 交易日历额外延长两个交易日；这两天只用于取得入场价和退出价，不产生新的测试信号。

该口径仍是假设可以按官方开盘价成交的教学性简化。停牌、涨跌停、集合竞价未完全成交、滑点和冲击成本仍需由交易模拟器单独处理。

### 3.4 等权合成没有处理因子方向

原脚本按 `abs(IC)` 选择因子，却直接对标准化因子求均值。负 IC 因子虽然可能具有预测能力，但含义是“因子越大、未来收益越低”，直接正向相加会把有效信号反着使用。

当前等权合成仅使用训练期 IC 确定方向：

```python
direction = np.sign(train_ic)
score = mean(direction[factor] * factor_value[factor])
```

正 IC 因子保持不变，负 IC 因子乘以 `-1`，使校正后的所有因子都表示“数值越大，预期收益越高”。这组方向随后固定应用于 train、valid 和 test，不能根据验证期或测试期表现回头调整；验证集只用于观察合成 IC 是否仍然有效。线性回归会自行学习系数正负，因此不需要重复翻转输入因子。

固定训练期方向仍隐含“因子方向在样本外保持稳定”的假设。更进一步可以使用滚动 IC 或衰减 IC，但必须确保每个时点只使用当时已经结束的历史数据。

### 3.5 回测末端少算收益、多收成本

原脚本仅依靠 `prev_set` 隐式移动持仓，最后一次新建仓位可能没有获得后续收益却已经被扣除成本。当前回测改为通过交易日历显式建立：

```text
信号日 T → T+1 开盘成交 → T+2 开盘退出/调仓
```

当前代码将“信号截止日”和“结算行情截止日”分开：信号只生成到 `TEST_END`，行情则自动读取到其后的第二个交易日。因此，最后两个测试信号也能获得完整的 T+1 入场价和 T+2 退出价；若数据源仍缺少必要日期，防御性检查会跳过该笔交易，避免产生只有成本、没有收益的孤立仓位。

回测末端采用“最终清仓”口径。最后一个收益区间在 T+2 开盘估值后，将剩余持仓全部卖成现金，并额外计入一次清仓换手和卖出成本。这样结果表示可落袋的现金净值，而不是尚未支付退出成本的持仓市值。

## 4. 组合和交易模拟问题

### 4.1 等权收益与换手率计算不一致

脚本每天使用持仓股票收益的简单平均，这相当于每天把组合恢复为等权；但换手率只根据股票集合的变化计算，忽略了股票涨跌造成的权重漂移及恢复等权产生的交易。

标准做法应根据真实权重计算：

```text
换手率 = 0.5 × Σ|目标权重 - 调仓前漂移权重|
```

如果脚本希望忽略每日再平衡，则收益也应根据上一日真实漂移后的持仓权重计算，而不能每日重新取简单平均。

### 4.2 缺失收益被删除后重新分配资金

相关代码：第 127～131 行。

```python
period_rets = (
    test_open_wide.loc[exit_date, valid_stocks]
    / test_open_wide.loc[entry_date, valid_stocks]
    - 1
).dropna()
port_ret = period_rets.mean()
```

如果一只持仓股停牌，代码会将其删除，并把组合资金重新平均分配给其他股票，相当于无成本、提前完成资金转移。

更合理的处理是保留停牌股票的持仓权重，按照明确的估值规则处理收益，并限制其买卖。

### 4.3 交易成本模型过于简化

统一使用 `0.1% × 换手率` 没有区分：

- 买入佣金与卖出佣金；
- 卖出印花税；
- 滑点和市场冲击；
- 涨停无法买入、跌停无法卖出；
- 停牌；
- 最低佣金和资金规模。

教学脚本可以采用简化成本，但应明确该模型是理想化假设。对于 Top30 日频调仓策略，交易约束和冲击成本可能显著改变结论。

### 4.4 股票数量不足时分母仍固定为 TOPK

换手率分母固定使用 `TOPK`。如果某日有效股票不足、部分股票因数据或交易限制无法持有，实际持仓数可能小于 `TOPK`，此时换手率会计算错误。

最终应统一转换为权重向量计算收益和换手，而不是根据股票只数近似。

## 5. 基准问题

相关代码：第 447～448 行。

```python
benchmark_ret = (
    test_open_wide.loc[exit_date]
    / test_open_wide.loc[entry_date]
    - 1
).mean()
```

`test_open_wide` 的列是整个研究期间内曾属于 CSI300 的股票合集。因此这个基准可能包含：

- 当时尚未进入 CSI300 的股票；
- 已经退出 CSI300 的股票；
- 因缺失值而每日动态改变权重的股票。

它既不是真实 CSI300 指数，也不是严格的当日 CSI300 成分股等权组合。

建议优先使用真实 CSI300 指数收益作为基准；如果希望构造等权基准，则必须按每个日期的有效成分区间建立当日股票池，并使用与策略一致的收益、停牌和调仓规则。

## 6. 模型和研究流程问题

### 6.1 普通线性回归与选股目标不完全一致

相关代码：第 383～399 行。

当前 OLS 将所有“日期 × 股票”样本合并，优化个股下一日收益的均方误差，但策略最终关心的是每日截面排序和 Top-K 收益。

主要问题包括：

- 损失函数不是 Rank IC 或组合收益；
- 每日有效股票数不同，日期权重随之不同；
- `MOM_20D`、`MA_DEV` 等因子可能高度相关，OLS 系数不稳定；
- 标签中的极端值对 OLS 影响较大；
- 没有正则化和时间序列交叉验证。

教学阶段可先改用 Ridge，并通过按时间切分的验证集选择正则化参数。标签也可以按日去均值、标准化或转换成截面 rank，使模型目标更接近选股目标。

### 6.2 验证集没有真正参与决策

脚本虽然展示了 EW 和 LR 在验证集上的 IC，但没有明确：

- 根据什么规则选择最终方法；
- 是否使用验证集选择因子阈值、TopK 或模型参数；
- 确定方案后是否用 train+valid 重新训练。

建议明确三区间职责：

```text
训练集：拟合模型参数
验证集：选择因子、模型、超参数和组合规则
测试集：最终只评估一次
```

不应看完测试集上 EW 与 LR 的表现后，再宣布表现更好的方法有效。

### 6.3 因子筛选结果存在样本内乐观偏差

训练集同时用于计算 IC、筛选因子以及展示筛选后组合的训练期 IC。筛选后的训练期结果天然偏高。

因子的真实判断依据应是验证期、滚动样本外 IC，以及不同市场阶段中的稳定性。还应补充 IC t 值、分组收益和多空收益，而不只依赖固定的 `|IC| > 0.02` 阈值。

### 6.4 ICIR 口径需要明确

当前 ICIR 定义为：

```text
IC 均值 / IC 标准差
```

这是可用的一种未年化定义，但部分研究平台会乘以 `sqrt(252)` 做年化。报告中必须注明口径，经验阈值不能在不同定义间直接套用。

## 7. 绩效指标问题

相关代码：第 88～102 行。

### 7.1 夏普比率不是常用定义

当前使用：

```text
几何年化收益 / 年化波动率
```

更常见的日频夏普是：

```text
(日均收益 - 日均无风险收益) / 日收益标准差 × sqrt(252)
```

两种结果可能明显不同，应采用常见定义并注明是否扣除无风险收益。

### 7.2 最大回撤可能漏掉第一天亏损

净值序列直接从第一日收益后的值开始，没有在最前面补初始净值 1。如果第一天亏损，`cummax()` 可能把亏损后的净值视为初始高点，从而漏掉这段回撤。

应在净值序列前补一个初始值 1，再计算最大回撤。

### 7.3 缺少相对基准指标

建议补充：

- 年化超额收益；
- 信息比率；
- 跟踪误差；
- 相对最大回撤；
- 月度胜率；
- 换手率和成本侵蚀；
- 分年度、分市场阶段表现。

## 8. 合理的教学简化，但需要明确披露

以下内容不属于直接程序错误，但会限制研究结论：

- 未进行行业和市值中性化，因子 IC 可能来自行业、规模或 Beta 暴露。
- Top30 纯多头组合没有行业上限、个股权重上限和风格约束。
- 测试期约 19 个月，覆盖的市场状态有限。
- `TURN_5D` 实际是成交量比，不是真正的换手率，命名容易误导。
- `TURN_5D` 的五日均量包含当日成交量；若想衡量成交量异常，可与此前五日均量比较。
- 因子定义较基础，没有检验冗余性、相关性和分组单调性。
- `warnings.filterwarnings("ignore")` 可能掩盖 Pandas 行为变化和数据异常。
- 数据路径与输出路径硬编码，不利于迁移和复现。
- 未记录 Python、Pandas、Qlib、数据版本和随机种子等实验环境信息。

## 9. 值得保留的设计

该脚本仍有一些适合教学的结构，可以在改造时保留：

- train、valid、test 按时间顺序切分，没有随机打乱时间序列。
- rolling 因子先使用完整历史计算，再准备按成员区间选股的思路是正确方向。
- 每日截面去极值和标准化适合多因子选股框架。
- 同时展示等权和模型合成，有助于理解简单基线与统计模型的区别。
- 将因子、组合和绩效步骤清晰拆分，便于继续模块化。

## 10. 建议实施顺序

### 第一阶段：消除偏差并统一时间口径

1. 将因子数据和监督学习标签分开管理。
2. 在截面处理前按日期过滤当日 CSI300 成分股。
3. 明确信号、成交和收益区间，消除同收盘成交假设。
4. 重写回测日期映射，修复末端收益与成本错配。
5. 按训练期 IC 方向处理等权因子，并在验证集确认方向稳定性。

### 第二阶段：建立可信的组合回测

1. 使用权重向量而不是股票集合表示持仓。
2. 根据漂移权重计算组合收益和真实换手。
3. 加入停牌、涨跌停和无法成交处理。
4. 分离买入成本、卖出成本、印花税和滑点。
5. 使用真实 CSI300 指数或严格构造的当日等权 CSI300 基准。

### 第三阶段：完善模型与验证

1. 使用验证集选择因子、模型、TopK 和正则化参数。
2. 使用 Ridge 或其他稳定模型替代裸 OLS 基线。
3. 增加滚动训练或 walk-forward 样本外检验。
4. 补充分组收益、Rank IC、IC t 值、因子相关性和稳定性分析。
5. 确定研究方案后，测试集只评估一次。

### 第四阶段：完善报告与复现

1. 统一绩效指标定义。
2. 增加超额收益和风险归因。
3. 保存配置、环境、数据版本及每次运行时间。
4. 输出每日信号、目标权重、实际持仓、交易记录和成本明细，方便审计。

## 11. 最终判断

完成第一阶段后，该脚本可作为基本可信的量化教学示例；完成第二阶段后，才适合比较策略和基准表现；完成滚动样本外检验、交易约束与风险归因后，才具备进一步讨论实盘价值的基础。

在当前版本下，最重要的不是继续增加复杂因子或模型，而是先消除前视偏差、统一成交时点，并让组合收益、持仓权重、换手率和交易成本使用同一套会计口径。
