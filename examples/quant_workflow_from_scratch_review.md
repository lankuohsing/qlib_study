## 3. 已修复的高优先级问题

### 3.1 打分股票池不再参考未来标签

当前代码第 526～552 行将数据明确拆为两种用途：

```python
scoring_df = processed.dropna(subset=FACTOR_COLS)
labeled_df = scoring_df.dropna(subset=["LABEL"])

train_df = segment(labeled_df, TRAIN_START, TRAIN_END)
valid_df = segment(scoring_df, VALID_START, VALID_END)
test_df  = segment(scoring_df, TEST_START, TEST_END)
```

含义是：

- 训练和 IC 检验需要同时具有因子和标签；
- valid、test 和实盘式打分只要求当时因子可用；
- valid/test 的标签只能在得分生成后用于事后评价，不能用来决定给哪些股票打分。

当前标签是 T+1 开盘至 T+2 开盘的未来收益。如果某只股票未来停牌、退市或缺少开盘价，`LABEL` 可能为空，但这不能成为 T 日提前排除该股票的理由。该问题已经修复；真正的无法成交仍应由交易模拟处理。

### 3.2 当日 CSI300 过滤已提前到截面预处理之前

当前代码第 506～524 行采用正确顺序：

```text
完整历史行情
→ 为每只股票计算 rolling 因子
→ 按日期过滤当日 CSI300 成分股
→ 在当日股票池内做 MAD 去极值和 Z-Score
```

保留入选前行情是为了给 rolling 窗口预热；但入选前或退出后的股票不能参与当日横截面均值、标准差、中位数和 MAD 的计算。当前实现已经把二者正确分开，避免未来成分股或已退出成分股污染历史截面。

### 3.3 信号、成交和标签时间已经统一

当前采用以下交易口径：

```text
T 日收盘：完整行情确定并生成信号
T+1 日开盘：买入或调仓
T+2 日开盘：卖出或再次调仓
```

标签位于当前代码第 468～470 行：

```python
LABEL = open_.shift(-2) / open_.shift(-1) - 1
```

即：

```text
LABEL[T] = open[T+2] / open[T+1] - 1
```

这个口径解决了“使用 T 日完整收盘数据后仍按 T 日收盘价成交”的时间矛盾，也满足普通 A 股当天买入后不能当天卖出的 T+1 交易限制。

当前实现不再假设所有目标都能成交：开盘价必须有效且成交量大于 0 才能买卖。不过，OHLCV 无法告诉我们涨停时是否实际买得到、跌停时是否实际卖得掉，也没有集合竞价成交量、滑点和市场冲击，因此仍是简化模型。

### 3.4 等权合成已按训练期 IC 统一因子方向

当前代码第 614～629 行先根据训练期 IC 确定方向：

```python
train_ic = ic_table.loc[valid_factors, "IC均值"]
factor_directions = np.where(train_ic >= 0, 1.0, -1.0)
```

随后将同一组方向固定应用于 train、valid 和 test：

```python
score = mean(direction[factor] * factor_value[factor])
```

正 IC 因子保持不变，负 IC 因子乘以 `-1`，使校正后的所有因子都表达“数值越大，预期收益越高”。方向只使用训练期信息，不能根据验证期或测试期结果回头修改，否则会产生泄漏。

线性回归会自行学习系数正负，因此 LR 路径没有重复翻转输入因子。固定训练期方向仍隐含“方向在样本外保持稳定”的假设，后续可以考虑只使用历史信息的滚动 IC 或衰减 IC。

### 3.5 回测末端收益与成本已经显式对齐

当前代码第 132～143 行通过交易日历明确建立：

```text
信号日 T → T+1 开盘入场 → T+2 开盘退出/调仓
```

当前代码第 384～396 行还会自动寻找 `TEST_END` 之后的两个交易日。信号仍然只生成到 `TEST_END`，额外行情只用来提供最后一个信号所需的 T+1 入场价和 T+2 结算价，不会产生新的测试信号。

若某日没有新信号，回测会继续持有原仓位并记录当日 open-to-open 收益，而不是跳过这段时间。

回测末端会尝试清仓：只卖出最后结算日可交易的股票，并仅对实际卖出额收取成本。如果仍有无法卖出的持仓，它们会按最后有效价继续估值，并通过 `frozen_count`、`frozen_weight` 和期末 `cash_weight` 披露，不伪装成已全部变现。

## 4. 组合权重与交易模拟

### 4.1 等权收益、换手和成本已统一到实际账户

这里的“等权收益”是指：选出 Top30 后，策略希望把资金平均分给 30 只股票，每只目标权重是 `1/30`。它不是“多个因子等权合成股票得分”，也不是“基准股票等权”；EW 和 LR 两种打分方法选股后都使用这个 Top30 等权目标。扣除成本、买单按现金等比缩放或发生成交失败后，实际权重可能偏离 `1/30`，回测使用的是这些实际持仓，而不是强行使用目标权重。

原实现直接对股票收益求平均，却只按股票名单变化估算换手。当前代码第 109～365 行已改为状态化账户：回测从 1 元初始资产出发，逐日记录每只股票的实际股数和现金。

```python
actual_holdings[stock] += filled_value / trade_price
cash -= filled_value * (1.0 + TRANSACTION_COST)
```

具体流程是：

- Top-K 仍是希望达到的等权目标；
- 先按当日开盘价计算实际持仓市值，再卖出超配或移出目标的可交易股票；
- 用真实可用现金按比例买入可交易股票，所以不会隐式借钱；
- 日收益来自同一账户前后两个开盘时点的净值变化；
- `buy_turnover`、`sell_turnover`、`turnover` 和 `transaction_cost` 全部由实际成交额计算。

因此，即使股票名单完全相同，价格涨跌造成的权重漂移也会导致真实再平衡交易；如果交易失败，实际持仓则不会被强行改成目标持仓。

### 4.2 缺失价格不再触发免费重分配或虚假成交

原来的 `period_rets.fillna(0.0)` 已删除。当前代码第 154～268 行将估值和可交易性分开处理：

- **目标股入场日缺价或零成交量**：不买入，不收手续费，资金留在现金。
- **已持有股票在调仓日缺价或零成交量**：不卖出，股数不变，用最后有效价估值并记为冻结持仓。
- **价格和成交量恢复后**：下一次调仓再根据当时目标尝试买卖。
- **成本**：仅对实际买入额和卖出额收取。

`membership_dict` 只决定某只股票在信号日是否有资格进入候选池，不用来判断调仓日能否成交。可交易性只由当日有效开盘价和正成交量的简化规则决定。

`unfilled_buy_count` 只统计因开盘价无效或成交量不大于 0 而完全无法下单的目标股；为预留手续费或受现金限制而发生的等比缩小不计入该数字。`unfilled_sell_count` 则记录应当减仓、但当日不可交易的持仓数。

例如原计划把 300 元平分给 A、B、C，但 C 在入场日不可交易，现在的实际账户是 A、B 各约 100 元，C 的约 100 元仍是现金；不会把它免费分给 A、B，也不会伪造 C 的交易。

本节原问题在现有 OHLCV 数据能力内已修复，但“最后有效价”只是估值规则，不是真实可变现价值。当前数据还无法区分停牌与纯数据错误，也无法精确模拟涨跌停封单、ST、退市、复权异常、公司行为和部分成交。

### 4.3 交易成本模型仍过于简化

当前统一费率为：

```python
TRANSACTION_COST = 0.001
cost = (actual_buy_amount + actual_sell_amount) * TRANSACTION_COST
```

它没有区分：

- 买入佣金与卖出佣金；
- 卖出印花税；
- 最低佣金；
- 开盘滑点和市场冲击；
- 涨停无法买入、跌停无法卖出；
- 真实停复牌状态和部分成交；
- 资金规模与成交量约束。

这比原先的“换手率 × 费率”更严格：买入和卖出都分别按实际成交额收费，未成交部分不收费。但买卖仍使用同一费率，因此结果只能理解为简化成本敏感性示例。

### 4.4 固定 `TOPK` 分母问题已经消除

当前目标金额使用 `调仓前净值 / len(target_stocks)`，实际换手则由真实买卖额除以净值得到，因此不再依赖固定 `TOPK` 分母。即使当日只有不足 30 只可选股，或部分目标买入失败，账户仍按实际成交记账。

## 5. 基准仍不严格

当前代码第 726～735 行已将基准收益区间与策略记录的开盘到次日开盘区间对齐，但基准股票池仍来自 `test_open_wide` 的全部列：

```python
benchmark_ret = (
    test_open_wide.loc[exit_date]
    / test_open_wide.loc[entry_date]
    - 1
).mean()
```

这些列是整个研究期间内曾经属于 CSI300 的股票合集，因此基准可能包含：

- 当时尚未进入 CSI300 的股票；
- 已经退出 CSI300 的股票；
- 因缺失值而每日动态改变权重的股票。

它既不是真实 CSI300 指数，也不是严格的当日 CSI300 成分股等权组合。策略还扣除了简化交易成本，而基准没有相同的调仓和成本过程，二者并非完全可比。

建议优先使用经过一致复权和时间对齐的真实 CSI300 指数 open-to-open 收益；如果希望构造等权基准，则必须使用每个日期的有效成分股、真实权重漂移、相同成交限制和相同成本规则。

## 6. 模型和研究流程问题

### 6.1 普通线性回归与选股目标不完全一致

当前代码第 652～669 行把所有“日期 × 股票”样本合并，使用普通线性回归优化个股未来 open-to-open 收益的均方误差，但策略最终关心的是每日截面排序和 Top-K 组合收益。

主要问题包括：

- 损失函数不是 Rank IC 或组合收益；
- 每日有效股票数不同，样本多的日期权重更高；
- `MOM_20D`、`MA_DEV` 等因子可能高度相关，OLS 系数不稳定；
- 标签极端值会明显影响均方误差；
- 没有正则化和时间序列交叉验证。

教学阶段可先改用 Ridge，并通过按时间切分的验证集选择正则化参数。标签也可以按日去均值、标准化或转换成截面 rank，使模型目标更接近选股目标。

### 6.2 验证集仍未真正驱动最终决策

当前代码第 671～691 行会展示 EW 和 LR 的 valid IC，这是正确的评价步骤；但脚本没有明确：

- 根据什么规则选择最终使用 EW 还是 LR；
- 是否使用 valid 选择 IC 阈值、TopK 或正则化参数；
- 选择方案后是否使用 train+valid 重新训练；
- 测试集结果是否只查看一次。

建议明确三区间职责：

```text
训练集：拟合参数并估计因子方向
验证集：选择因子、模型、阈值、TopK 和超参数
测试集：冻结所有规则后只进行一次最终评价
```

### 6.3 因子筛选仍有样本内乐观偏差

当前训练集同时用于计算 IC、按 `|IC| > 0.02` 筛选因子，以及展示筛选后组合的训练 IC。筛选后的训练结果天然偏高。

更可靠的判断应来自验证期或滚动样本外 IC，并补充：

- IC t 值；
- Rank IC 稳定性；
- 分组收益和多空收益；
- 因子相关性和冗余性；
- 分年度、分市场阶段表现。

### 6.4 ICIR 口径需要明确

当前 ICIR 定义为：

```text
IC 均值 / IC 标准差
```

这是未年化口径。部分研究平台会乘以 `sqrt(252)` 做年化，因此经验阈值不能在不同口径之间直接套用。脚本已经打印定义，但报告结果时仍应明确标注“未年化 ICIR”。

## 7. 绩效指标问题

相关代码：第 92～106 行。

### 7.1 夏普比率不是常用定义

当前使用：

```text
几何年化收益 / 年化波动率
```

更常见的日频夏普是：

```text
(日均收益 - 日均无风险收益) / 日收益标准差 × sqrt(252)
```

两种定义可能明显不同，应改用常见口径并注明是否扣除无风险收益。

### 7.2 最大回撤可能漏掉第一期亏损

当前净值直接从第一期收益后的值开始，没有在序列最前面补初始净值 1。如果第一期亏损，`cummax()` 会把亏损后的净值当成最初高点，从而漏掉从 1 到该净值的回撤。

应在净值序列前补一个初始值 1，再计算最大回撤。

### 7.3 缺少相对基准和成本分析指标

建议补充：

- 年化超额收益；
- 信息比率和跟踪误差；
- 相对最大回撤；
- 月度胜率；
- 毛收益、交易成本和净收益拆分；
- 分年度、分市场阶段表现。

## 8. 合理的教学简化，但需要明确披露

以下内容不属于直接程序错误，但会限制研究结论：

- 未进行行业和市值中性化，因子 IC 可能来自行业、规模或 Beta 暴露；
- Top30 纯多头组合没有行业上限、个股权重上限和风格约束；
- 回测使用小数股，未模拟 A 股通常的 100 股整手买入、零股卖出和最小佣金约束；
- 测试期约 19 个月，覆盖的市场状态有限；
- `TURN_5D` 实际是成交量比，不是真正的换手率；
- `TURN_5D` 的五日均量包含当日成交量；若衡量异常放量，可与此前五日均量比较；
- 因子定义较基础，没有检验冗余性、相关性和分组单调性；
- `warnings.filterwarnings("ignore")` 可能掩盖 Pandas 行为变化和数据异常；
- 数据提供路径和输出目录仍依赖本地环境；
- 未记录 Python、Pandas、Qlib、数据版本和随机种子等实验环境信息。

## 9. 当前值得保留的设计

- train、valid、test 按时间顺序切分，没有随机打乱时间序列；
- rolling 因子使用完整历史预热，同时按当日成员区间构建截面；
- 打分集和有标签数据集已经分开管理；
- 信号、成交、收益和结算日期映射清晰；
- 等权方向只从训练集估计并冻结到样本外；
- 组合收益、实际换手、现金、成本、冻结持仓和期末清仓已使用同一套持仓账户；
- 每日截面 MAD 去极值和 Z-Score 适合多因子选股教学；
- 同时展示等权与线性回归合成，有助于比较简单基线和统计模型；
- 输出信号日、入场日、退出日、买卖换手、成本、现金权重、冻结权重和未成交数，便于继续审计。

## 10. 后续建议实施顺序

### 已完成：消除主要偏差并统一基础会计口径

1. 分离打分数据和有标签数据。
2. 在截面预处理前过滤当日 CSI300 成分股。
3. 统一为 T 收盘信号、T+1 开盘入场、T+2 开盘退出/调仓。
4. 使用交易日历结算测试末端，并计入最终清仓成本。
5. 按训练期 IC 方向处理等权因子。
6. 使用实际持股数和现金账户统一计算收益、换手和成本。
7. 缺价或零量时买入留现金、卖出留冻结持仓，不再免费重分配或伪造成交。

### 下一阶段：补充 OHLCV 无法提供的真实交易状态

1. 加入停复牌、涨跌停价和 ST/退市状态等专用数据。
2. 使用集合竞价成交量、资金规模和参与率模拟部分成交。
3. 将纯数据缺失与真实停牌分开，对数据异常主动报警。
4. 分离买入佣金、卖出佣金、印花税、滑点和市场冲击。
5. 使用真实 CSI300 指数或严格构造的当日等权 CSI300 基准。

### 第三阶段：完善模型与验证

1. 使用验证集选择因子、模型、TopK 和正则化参数。
2. 使用 Ridge 或其他稳定模型替代裸 OLS 基线。
3. 增加滚动训练或 walk-forward 样本外检验。
4. 补充分组收益、Rank IC、IC t 值、因子相关性和稳定性分析。
5. 冻结研究方案后，测试集只评估一次。

### 第四阶段：完善绩效与复现

1. 统一夏普、最大回撤和超额指标定义。
2. 增加收益、风险和成本归因。
3. 保存配置、依赖版本、数据版本和运行时间。
4. 输出逐笔委托/成交、持仓快照和数据质量告警，方便进一步审计。

## 11. 最终判断

当前版本已经完成原审阅“第一阶段”的主要任务：直接前视偏差、股票池截面污染、同收盘成交假设、因子方向和回测末端错配均已修复。它现在适合作为基本可信的量化流程教学示例。

组合收益、换手和成本现在已使用同一个实际持仓/现金账户，缺失收益按 0 和目标交易虚假成交的问题已经消除。但仅用 OHLCV 无法还原涨跌停封单、ST/退市、部分成交和数据错误，统一成本率、非严格基准和绩效指标口径也可能显著影响结果。因此，当前版本是更可信的教学回测，但其年化收益与夏普比率仍不应直接解释为可实现的实盘绩效。
